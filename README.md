![](https://img.shields.io/github/v/release/jayibidi/UGAEO.svg)
![](https://img.shields.io/github/last-commit/jayibidi/UGAEO)

**开源免费**的跨平台文章同步工具 | Chrome 浏览器扩展 | 自媒体内容分发神器

一键同步微信公众号文章到知乎、头条、掘金、小红书、CSDN 等 31 个平台，支持 WordPress / Typecho 等自建博客，告别重复复制粘贴。

> 🔥 支持 **Anthropic MCP 协议**，可在 Claude Desktop / Claude Code 中通过 AI 一键发布文章

## 工作原理

**文章同步助手不是爬虫，不模拟登录，不经过任何第三方服务器。**

它是一个 Chrome 浏览器扩展，工作方式与浏览器本身一致：

1. **使用你自己的登录态**：你在浏览器里正常登录各平台账号，扩展直接使用浏览器中已有的 Cookie，无需额外授权，无需输入密码
2. **调用平台官方接口**：发布文章时，扩展调用的是各平台 Web 编辑器使用的同一套官方 API，与你手动在网页上发布完全等价
3. **数据不离开你的设备**：所有请求直接从你的浏览器发往各平台，没有中间服务器，没有数据上传，源代码完全开源可审计
4. **草稿优先**：默认将文章同步为草稿，发布前由你人工确认，不会自动发布

```
你的浏览器（已登录各平台）
    ↓  扩展读取 Cookie
    ↓  调用平台官方 Web API
各平台（知乎 / 掘金 / 头条 / ...）
```

## 功能特性

- **一键批量发布**: 微信公众号文章同步到知乎、掘金、头条、CSDN、简书、微博、小红书等 31 个平台，其中 11 个可自动点下发布按钮
- **网页转 Markdown**: 任意网页智能提取正文，自动过滤广告噪音，图片本地化，打包为 Markdown + 图片 ZIP 压缩包
- **自建站支持**: WordPress、Typecho、博客园 (MetaWeblog API)
- **智能提取**: 自动从网页提取文章标题、内容、封面图（基于 Safari 阅读模式）
- **图片自动上传**: 自动转存文章图片到目标平台，无需手动处理
- **草稿模式**: 同步后保存为草稿，方便二次编辑后发布
- **自动发布**: 支持「立即发布 / 存为草稿 / 定时发布」三种模式，可按平台单独覆盖
- **发布后状态追踪**: 知乎、掘金发布后自动轮询审核状态（审核中 / 已发布 / 未通过）
- **AI 增强**: 接入 OpenAI 兼容中转站，支持标题优化、摘要、标签推荐、润色/扩写/精简、多平台风格改写
- **独立 WEB 控制台**: 点「同步」进入完整网页，集中查验多账号登录态、查看同步失败明细、发布失败一键返回编辑重发
- **AI 集成**: 支持 Anthropic MCP / Claude Code Skill / OpenClaw，多种方式接入 AI 工作流

## 自动发布与 AI 增强

### 发布模式

设置 → 发布模式：

| 模式 | 行为 |
|-----|------|
| 存为草稿 | 默认，仅创建草稿 |
| 立即发布 | 同步时直接公开发布 |
| 定时发布 | 入队，N 分钟后由浏览器自动执行 |

- 支持**按平台覆盖**：没有声明 `publish` 能力的平台会自动降级为草稿，并在结果里标注「该平台暂不支持自动发布，已保存为草稿」
- 已实现真正公开发布的平台：**知乎、掘金、CSDN、博客园、WordPress、Typecho、MetaWeblog**
- **小红书、头条号**通过「页面驱动」发布：平台 Web 接口带 `_signature` / `x-s` 等反爬签名，只能在页面上下文生成，因此扩展会打开（或复用）创作者编辑器，在页面里填入标题与正文，再触发平台的发布按钮：
  - 检测到成功反馈 → 记为已发布
  - 已点击但无法确认 → 记为「已提交」，提示去平台确认
  - 找不到发布按钮（页面改版 / 未登录） → 内容留在编辑器，按草稿返回并给出编辑器链接
  - 被重定向到登录页时直接提示「请先登录该平台」，不会含糊地报「页面结构已变化」
  - 草稿模式会点平台自己的「存草稿 / 保存草稿」，内容真的进草稿箱，而不是只留在编辑器里
  - **小红书目前只接「写长文」**：先点左侧「写长文」→「新的创作」进编辑器。上传图文 / 视频 / 播客需要图片或音视频素材，暂未接入
  - 头条号打开编辑器时会自动关掉「未发布草稿 / 新手引导」遮挡，只点「继续编辑 / 我知道了」，绝不点「放弃」
- **快懂百科、百度知道**是纯人工平台（词条编辑 / 问答），扩展只打开入口页并说明要做什么，不会注入内容——硬填只会把标题写进站内搜索框
- 微博、B 站这类「有编辑器、没有直发接口」的平台归第二层「AI 自动发布」：AI 改好标题 / 摘要 / 标签后填表并点发布，点不到就退回草稿（见下文三层说明）

### 草稿 → 发布两步走（控制台）

控制台「同步」页右侧的「发布设置」有两条路径，行为和可选平台都不一样：

| 页签 | 同步到哪些平台 | 产出 | 下一步 |
|---|---|---|---|
| **存为草稿** | 所有已登录平台 | 只写草稿箱，绝不公开发布 | 勾选成功的草稿，一键带入「立即发布」 |
| **立即发布** | 已登录 + 能自动发布的平台（可直发 11 + AI 自动发布 14 = 25），第三层「词条平台」锁住 | 直接公开发布（点不到按钮就退回草稿） | 可选「立即」或「定时」，定时需选具体时间 |

- **立即发布 = AI 自动发布**：选了「立即发布」就会调用 AI，为每个平台生成适配标题、摘要与标签，
  再把这些内容填进发布页并点下发布按钮（详见下节）
- **定时发布**在控制台里直接选日期时间，入队后由浏览器到点执行（关闭浏览器则顺延到下次启动）
- **草稿转发布**只对声明 `publish_existing_draft` 的平台自动完成（当前是**知乎、掘金**）：直接发布**原来那篇草稿**，不会新建第二篇
- 其余平台没有「发布已有草稿」的接口，界面会标成「需手动发布」并给出草稿链接 —— 宁可让用户点一下，也不悄悄创建重复内容
- 控制台刷新后带入的草稿不会丢（存在本地 `pendingDraftRefs`），但只保留最近一次草稿同步的结果

### AI 自动发布怎么跑

「立即发布」不是把同一篇稿子原样塞进所有后台：每个平台的标题上限、标签习惯、摘要长度都不一样。
所以发布前会走一遍**发布计划**，一次调用拿到三样东西：

```
{ "title": "适配后的标题", "summary": "一句话摘要", "tags": ["话题1", "话题2"] }
```

| 环节 | 做什么 | 失败时 |
|---|---|---|
| 生成计划 | 按平台标题上限（小红书 20 / B站 40 / 知乎 100 …）、标签数量（小红书 8、微博 3、技术社区 5）一次生成标题 + 摘要 + 标签 | 退回规则标题、不填标签，发布照常进行 |
| 填表 | 标题、正文、摘要、标签逐项填进发布页；没有标签框的平台（小红书长文）把 `#话题` 追加到正文末尾 | 缺哪项就在结果里写清缺哪项 |
| 点发布 | 按「发布 / 发布笔记 / 提交」文案找按钮，必要时走「一键排版 → 下一步 → 发布」多段流程 | 找不到按钮时明确写出「停在哪一页」，不假装成功 |

- 一次计划只调 **一次**模型（不是标题、摘要、标签各问一遍），单平台 9 秒超时、3 并发、最多 25 个平台
- AI 没配置时界面会直说「本次只用规则标题」，不会让人以为已经改写过
- 点按钮始终由脚本执行 —— 让模型去读 DOM 点按钮既慢又不可靠，那是另一个数量级的成本

### 发布后审核状态

知乎、掘金的「发布成功」只代表提交成功，文章还要过审才公开。扩展会在发布后按 5 秒间隔轮询文章状态（最长 30 秒，遇到确定结果立即返回）：

| 状态 | 展示 |
|-----|------|
| `published` | 已发布，文章已公开 |
| `reviewing` | 已提交，平台审核中 |
| `rejected` | 审核未通过（会带上平台给出的原因） |

轮询超时会如实显示「审核中」，不会把未确认的状态当成已发布。单平台同步结果里会有「审核中 / 未过审」标记。

### AI 接入

设置 → AI 模型：

1. **API 地址**默认 `https://api.ugooto-ai.com/v1`（任意 OpenAI 兼容中转站均可）
2. 填写 **API Key**（仅保存在 `chrome.storage.local`，不会上传）
3. 点「拉取模型」从 `/v1/models` 选择模型，也可手填模型名
4. 点「测试连接」验证
5. 可按需开关：标题优化 / 摘要生成 / 标签推荐 / 平台风格适配

同步对话框里的「AI 助手」面板可直接使用这些能力；选择「适配 N 个平台」会为每个平台生成差异化 Markdown，同步时优先使用该版本（`platformContents`），其余平台仍走原有 DOM 预处理。

**正文加工**：面板里另有「润色 / 扩写 / 精简」三个动作，针对当前正文做通用写作层面加工（不换平台调性），结果可一键「采用为正文」。采用后原有平台适配结果会被清空，避免同步时用回旧内容。

## WEB 控制台

扩展弹窗点「同步」不再原地弹小窗，而是打开独立网页控制台（`src/console/index.html`），当前文章与已选平台会一起交接过去。弹窗顶部的「控制台」按钮可随时进入。

| 页面 | 用途 |
|-----|------|
| 概览 | 登录平台数、近 7 天同步与失败统计、最近同步、未登录平台快捷入口 |
| 同步 | 文章预览 / 编辑、平台勾选、存草稿或直接发布（含定时）、草稿转发布、实时进度与逐平台结果 |
| 账号 | 每个平台真实的登录态（点「重新检测」按平台实测 Cookie）、去登录、自建站点连接测试与删除 |
| 记录 | 每次同步的完整明细，含审核状态、失败原因、草稿链接 |
| 失败处理 | 聚合近 1/7/30 天失败，按平台与类型（登录问题 / 发布问题）筛选，可「重试」「返回编辑」「去登录」 |
| 自检 | 逐平台验证「到底通不通」：轻量体检查配置矛盾，深度体检真开页面验登录 / 入口 / 选择器 / 试填 |

### 自检怎么用

两层，互不替代：

- **轻量体检**（进页面自动跑，不发网络请求）：比对适配器声明的能力与方法实现、Cookie 名与当前登录态，
  抓「声明能从草稿转发布却没实现方法」「页面驱动平台没配选择器」这类配置矛盾。每个平台一个结论：
  可直发 / AI 自动发布 / 词条平台 / 未登录。
- **深度体检**（点行尾「探测」，或顶部「全量页面体检」）：后台静默打开该平台入口页，用完即关、不保存，
  依次回答：有没有被踢到登录页 → 入口按钮（小红书「写长文 → 新的创作」）点不点得进去 →
  标题框 / 正文框命中哪个选择器、可见几个 → 发布按钮在不在 → 页面是不是空壳。
  勾上「试填验证」还会真写一段测试文字再读回来，确认受控组件也认这次输入（不点保存、不提交）。

每项都是 `pass / warn / fail / skip` + 一句具体结论，失败直接说断在哪一环，
行内可展开看选择器命中明细与入口步骤轨迹；「复制报告」出一份可直接贴出来的纯文本。

判定上做了几处「宁可少报也不误报」的取舍，都来自真实体检数据：

- **编辑器已就绪时，入口步骤没点到只算提示**。头条的「继续编辑」是恢复草稿的提示层，
  编辑器本来就在页面上，等它 8 秒再判失败属于纯误报。
- **编辑器已就绪时不判空壳页**。小红书长文编辑器就是空的，全页 44 个字完全正常。
- **被重定向到首页时只报「先登录」**，后面的标题/正文/发布全部转成 skip，
  不再顺手叠加三条「选择器已过期」的假故障。
- **未登录的平台自动跳过深度体检**（点「仍然探测」可强制），省掉每个平台 20 秒的白等。
- **纯人工平台不探测**：IT之家、InfoQ、快懂百科、百度知道连输入框都没有，只开页 + 说明。

失败后可**返回编辑**：控制台会按 `syncId` 读取正文快照（最多保留 10 份），在弹窗里改标题、摘要、标签、正文（Markdown / HTML 可切换），再选择平台重新发布；重发结果直接显示成功或失败原因。

账号密码、Cookie、文章快照都只存在浏览器本地（`chrome.storage.local`），控制台不会向任何服务器上传数据。

## 安装

> **最快的方式：把 zip 直接拖进扩展页。** 先打开 `chrome://extensions` 并开启「开发者模式」，再把 `ugaeo-<版本>.zip` 拖进去，弹窗点「添加扩展程序」即可。
> 如果拖进去只出现下载任务，说明开发者模式没开，或浏览器策略禁止——改用下面的「解压后加载」。

**方式一：下载 Release（推荐）**

1. 打开 [最新 Release](https://github.com/jayibidi/UGAEO/releases/latest)，下载 `ugaeo-<版本>.zip`
2. 打开 `chrome://extensions` → 右上角开启「开发者模式」
3. **把 zip 拖到页面上** → 点「添加扩展程序」

拖不动 / 被策略拦住时，改成解压安装：

1. 解压到**固定目录**（别放下载临时文件夹，Chrome 会记住这个路径）
2. 扩展页 →「开发者模式」→「加载已解压的扩展程序」→ 选解压出来的目录（能看到 `manifest.json` 的那一级）

| 浏览器 | 扩展管理页 | 备注 |
|---|---|---|
| Chrome | `chrome://extensions` | 需要内核 102+ |
| Edge | `edge://extensions` | 同上 |
| 360 极速浏览器 | 菜单 → 工具 → 管理扩展（或 `chrome://extensions`） | 需 X 版 / 13 以上（内核 108+）；老内核会提示「需要更高版本」 |
| QQ 浏览器 | `qqbrowser://extensions` | 同上 |

360 极速、QQ 浏览器还可以直接双击安装 Release 里的 `ugaeo-<版本>.crx`；Chrome 官方版从 2021 年起禁止本地 crx，Chrome 上请用 zip。

**方式二：从源码构建**

```bash
pnpm install
pnpm bundle        # 产出 ugaeo-<版本>.zip（manifest.json 在根目录，可直接拖入安装）+ 同目录安装说明
pnpm crx           # 可选：产出签名 crx，供 360 / QQ 双击安装
```

构建目标锁在 `chrome102`，产物不含 `??=`、静态块、`oklch()` 这类新语法，老内核不会整包报语法错误。

## 支持的平台

共 **31 个平台**，按「扩展能替你做多少」分成三层。分层由适配器声明推导（`capabilities` 是否含 `publish` + `noEditor`），不是文档里手写的：

| 层 | 数量 | 扩展做什么 | 判断依据 |
|---|---|---|---|
| 第一层 · 可直发 | 11 | 填内容 → 点发布按钮 → 确认结果 | `capabilities` 含 `publish` |
| 第二层 · AI 自动发布 | 14 | AI 改标题 / 摘要 / 标签 → 填表 → 点发布；点不到就退回草稿 | 有编辑器、没有 `publish` |
| 第三层 · 词条平台 | 6 | 只打开入口页 + 说明要人工填什么，**一次注入都不发** | `meta.noEditor` |

## CLI 命令行工具

最简单的使用方式，无需配置 MCP，安装即用：

```bash
npm install -g @ugaeo/cli
```

需要先安装 Chrome 扩展并在扩展设置中启用「MCP 连接」获取 Token，然后：

```bash
export UGAEO_TOKEN="你的token"

# 同步文章到多个平台
ugaeo sync article.md -p zhihu,juejin,csdn

# 查看平台登录状态
ugaeo platforms --auth

# 从浏览器当前页面提取文章
ugaeo extract -o article.md
```

## Claude Code / Claude Desktop 集成 (Anthropic MCP)

通过 Anthropic MCP 协议，可以在 Claude Code 或 Claude Desktop 中使用 AI 同步公众号文章到多个平台。

### 配置步骤

1. 构建项目: `pnpm build`
2. 在 Chrome 扩展设置中启用「MCP 连接」，并设置 Token
3. 在 `~/.claude/claude_desktop_config.json` 中添加配置：

```json
{
  "mcpServers": {
    "sync-assistant": {
      "command": "node",
      "args": ["/path/to/UGAEO/packages/mcp-server/dist/index.js"],
      "env": {
        "MCP_TOKEN": "your-secret-token-here"
      }
    }
  }
}
```

**重要**: `MCP_TOKEN` 必须与 Chrome 扩展中设置的 Token 一致。

### 使用示例

```
"帮我把这篇文章同步到知乎和掘金"
"检查下哪些平台已登录"
```

### 可用工具

| 工具 | 说明 |
|-----|------|
| `list_platforms` | 列出所有平台及登录状态 |
| `check_auth` | 检查指定平台登录状态 |
| `sync_article` | 同步文章到指定平台（草稿） |
| `extract_article` | 从当前浏览器页面提取文章 |
| `upload_image_file` | 上传本地图片到平台 |

详细文档见 [packages/mcp-server/README.md](packages/mcp-server/README.md)

## 常见问题

**Q: 这是什么工具？**

文章同步助手是一款开源免费的 Chrome 浏览器扩展，帮助自媒体作者、博主、内容创作者将文章一键同步到多个平台，避免重复复制粘贴，是自媒体运营必备的多平台发文工具。

**Q: 支持同步微信公众号文章吗？**

支持。可以直接从微信公众号编辑器提取文章，一键同步到知乎、头条、掘金等 31 个平台。支持公众号文章同步到头条号、公众号同步到知乎、微信文章同步到掘金等各种场景。

**Q: 支持 AI 写作工具吗？**

支持 Anthropic MCP 协议，可配合 Claude Desktop、Claude Code 等 AI 工具使用，实现 AI 写作、AIGC 内容一键发布。也可以配合 ChatGPT、GPT-4 等工具生成的文章使用。

**Q: 数据安全吗？会上传我的账号信息吗？**

不会。所有操作在本地浏览器内完成，你的 Cookie、文章内容、账号信息不经过任何第三方服务器。代码完全开源，可自行审计：[查看源码](https://github.com/jayibidi/UGAEO)

**Q: 明明登录了，账号页却显示「未登录」怎么办？**

先确认三件事：① 登录的是**这个浏览器**（不是手机 App 或其他浏览器）；② 平台账号已通过审核、处于可发文状态；③ 点一次「全部重新检测」——登录结论有 5 分钟缓存，旧的错误结论不会自动消失。

如果还是不行，多半是平台的登录态不在 Cookie 里（八方资源网、黄页88 这类老后台把身份放在服务端 Session 中）。扩展对这类平台会**短暂打开一个后台标签页**实测：访客会被重定向到登录页，登录用户则停在会员中心，据此判断真实状态，测完立刻关掉。你看到标签页一闪而过是正常的。

**Q: 和微小宝、新媒体管家、简媒、蚁小二有什么区别？**

文章同步助手是**开源免费**的，代码完全公开透明，无需付费订阅。作为浏览器扩展运行，数据本地存储，账号信息不上传，支持 MCP 协议可与 AI 工具集成。

**Q: 如何同步文章到多个平台？**

1. 安装 Chrome 浏览器扩展
2. 登录各平台账号（知乎、掘金、头条等）
3. 打开要同步的文章页面
4. 点击扩展图标，选择目标平台，一键同步
