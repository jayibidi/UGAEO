# 平台自检

判断「这个平台到底通不通」，不能只看账号页那句「已登录」。这里的每一层都可能单独出错。

## 四层验证

| 层 | 检查什么 | 出错时用户看到什么 |
| --- | --- | --- |
| 1. 配置 | 适配器存在、能力声明与实现一致、平台档案里有标签 | 标签错（说可直发其实只能人工提交）、平台缺分组 |
| 2. 登录态 | Cookie 名配对了没、是否真的命中 | 明明登录了显示未登录；或反过来谎报已登录 |
| 3. 入口页 | 入口地址能不能打开、会不会跳登录页、是不是 404 | 打开一个空白页 / 登录页，内容填不进去 |
| 4. 填充与发布 | 标题 / 正文 / 发布按钮选择器在当前页面还命中吗 | 提示「已填入」但用户打开一看是空的 |

第 1、2 层是纯配置和 Cookie，可以离线判断；第 3、4 层必须真开页面，会随平台改版失效。

## 用控制台「自检」页

打开控制台 → 左侧「自检」（`#/diagnostics`）。

**轻量体检**：进入页面自动跑，35 个平台一次出结果，不发任何网络请求。每个平台给三个状态：

- **正常**：配置一致、登录态与 Cookie 对得上（或本来就不需要登录）
- **待确认**：未登录（正常现象）、登录态与 Cookie 不一致等需要人看一眼的情况
- **有问题**：配置自相矛盾，例如「需要登录却没给 Cookie 名」「投稿型平台声明了可直发」

点「复制报告」可以把整张表连同问题清单复制成文本，方便贴给开发排查。

**深度体检**：只对页面驱动（打开网站填内容）的平台可用，点击行尾「探测」。它会：

1. 在后台静默开一个标签页打开该平台入口页（不抢焦点）
2. 等页面加载完（SPA 再多等 1 秒）
3. 注入脚本统计：标题候选选择器命中几个可见元素、正文选择器命中几个、发布按钮文案有没有匹配上
4. 关闭标签页，把结果贴在行内

结果怎么读：

- **标题 ✓ / 正文 ✓** —— 填充链路可用
- **发布键 ✗** —— 内容填得进去但找不到发布按钮，同步会降级成「填好等你自己点发布」，不是失败
- **要求登录** —— 入口页直接跳登录页，先在该站登录再回来探测
- 全 ✗ 且页面内容很少 —— 大概率入口地址过期（404）或页面大改版

> 每个平台开一个标签页，一次探测一个即可，别连点十几个。

## 没有账号，怎么验证一个平台是通的

1. **先看它属于哪层**：`仅草稿` 里的投稿型平台（IT之家、InfoQ、快懂百科）本来就没有发布按钮，
   能做到「打开投稿页 + 填入标题正文」就算通了，剩下的靠人点提交。
2. **用不需要登录的平台当对照组**：这类平台的 `无需登录` 是真实状态，
   它们的深度体检结果能验证整条链路（注入 → 填充 → 探测）本身是好的。
3. **登录态可以只看 Cookie**：自检页会显示「配置要求哪些 Cookie / 实际命中哪些」。
   命中数为 0 且状态说已登录，就是判断逻辑写错了；命中数大于 0 却说未登录，同样是 bug。
4. **发布环节必须有账号**：真发一篇是唯一能证明「发布成功」的方式。没账号时不要相信任何
   「已发布」的结论——代码里也只有三种结果：`published`（检测到成功反馈）、`submitted`（点了但没确认）、
   `filled`（填好了没发），后两种都会在 UI 上标明。

## 这一轮体检发现了什么

| 问题 | 影响 | 状态 |
| --- | --- | --- |
| 投稿型平台 `requiresAuth=false` 直接返回「已登录」 | InfoQ / 快懂百科 / IT之家 没账号也显示已登录 | 已修：新增 `authMode: 'public'`，界面显示「无需登录」 |
| 51CTO 适配器 id 是 `51cto`，平台档案写成 `cto51` | 该平台没有内容形态标签，统计时被算进默认分类 | 已修 |
| 弹窗打开就报 `Receiving end does not exist` | 扩展重载后的旧标签页取不到文章 | 已修（见 v2.4.1） |

## 回归测试

`packages/core/src/adapters/__tests__/adapter-consistency.test.ts` 把上面第 1 层能自动判断的规则固化成了断言，
每次 `pnpm test` 都会跑。新增平台时如果忘了登记档案、Cookie 名写空、入口地址与匹配片段对不上，
测试会直接失败并指出是哪个平台。

```bash
pnpm --filter @ugaeo/core test
```
