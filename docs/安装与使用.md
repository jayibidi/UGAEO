# UG·AEO 安装与首次跑通指南

本文按「构建 → 装进浏览器 → 跑通第一条同步」的顺序写，命令可直接复制。
环境：Windows（PowerShell / Git Bash 均可）、Chrome 或 Edge。

---

## 0. 前置条件

| 依赖 | 版本要求 | 检查命令 |
|---|---|---|
| Node.js | ≥ 20（推荐 22） | `node -v` |
| pnpm | ≥ 9（推荐 12） | `pnpm -v` |
| 浏览器 | Chrome 110+ / Edge 110+ | 地址栏输入 `chrome://version` |

没装 pnpm：

```bash
npm i -g pnpm
```

> 不建议在构建时用 `npx vite`，仓库根目录的配置对 vite 版本敏感（必须是 5.x）。

---

## 1. 构建

在仓库根目录 `C:\Users\jayib\Documents\Wechat` 执行：

```bash
# 首次 & 依赖变动后
pnpm install

# 生产构建（含类型检查）
pnpm build
```

成功的标志：终端最后出现 `✓ built in ~10s`，并生成：

```
packages/extension/dist/manifest.json
packages/extension/dist/src/popup/index.html
packages/extension/dist/src/console/index.html   ← WEB 控制台
```

常用补充命令：

```bash
pnpm typecheck   # 只跑类型检查
pnpm test        # 单元测试（core + extension）
pnpm dev         # 开发模式（不压缩 + sourcemap，改代码自动重载）
```

> 改了代码后：重新 `pnpm build`，然后到 `chrome://extensions` 点该扩展的「刷新」按钮，再刷新目标网页。

## 2. 装进浏览器（加载已解压扩展）

### Chrome

1. 地址栏打开 `chrome://extensions/`
2. 打开右上角 **开发者模式**
3. 点左上角 **加载已解压的扩展程序**
4. 目录选择：`C:\Users\jayib\Documents\Wechat\packages\extension\dist`
   （选 `dist` 这一层，不要选 `packages/extension`，也不要选 `dist/src`）
5. 列表出现「UG·AEO | 新媒体中心 2.4.0」即成功
6. 点工具栏拼图图标 → 把 UG·AEO 固定到工具栏

### Edge

`edge://extensions/` → 左下角「开发人员模式」→「加载解压缩的扩展」→ 同样选 `dist` 目录。

### 检查是否装对

- 点扩展图标能弹出面板（有「控制台 / 账号 / 设置」入口）
- 打开任意文章网页，页面右下角出现 UG·AEO 悬浮球
- 控制台直达地址：`chrome-extension://<扩展ID>/src/console/index.html`
  （扩展 ID 在 `chrome://extensions/` 卡片上可以看到）

### 分发/备份

```bash
pnpm bundle          # 构建 + 打包，产出仓库根目录的 ugaeo-v2.4.0.zip
# 或只打包已构建好的 dist：
node scripts/pack-extension.mjs
```

拿到 zip 的机器：**先解压**，再用「加载已解压的扩展程序」选中解压出来的文件夹（里面应直接看到 `manifest.json`）。

> ⚠️ 不要用 PowerShell 的 `Compress-Archive` 手工打包。Windows PowerShell 5.1 生成的 zip 条目名用反斜杠（`assets\icon-48.png`），Chrome 按 `/` 找路径会报
> `Could not load icon 'assets/icon-48.png' specified in 'action'`。
> 仓库里的 `scripts/pack-extension.mjs` 已强制使用 `/`，零依赖、跨平台，用它就行。

> 也可以直接把 zip 拖进 `chrome://extensions`，Chrome 会自动解包到
> `...\User Data\Default\UnpackedExtensions\`。但这样装的副本不便更新，日常开发建议直接用 dist 目录。

## 3. 跑通第一条同步（推荐先走「存为草稿」）

### 3.1 先登录目标平台

在**同一个浏览器**里手动登录你要发布的平台（知乎、掘金、CSDN 等）。
扩展不模拟登录，直接复用你已有的 Cookie；没登录的平台会在控制台显示「未登录」。

同时准备好**源文章**：可以是一篇微信公众号文章（`mp.weixin.qq.com/s/...`），
也可以是任意网页文章——扩展会提取正文。

### 3.2 配置 AI（可选）

1. 点扩展图标 → **设置** → **AI 模型**
2. 打开「启用 AI 能力」
3. API 地址默认已是 `https://api.ugooto-ai.com/v1`，留空也用这个
4. 填 API Key → 点「拉取模型」→ 选一个模型（如 `gpt-4o-mini`）
5. 保存

失败会给出中文原因：401 Key 无效、402 余额不足、404 地址或模型不存在、429 限流。

### 3.3 选发布模式

设置 → **发布模式**：

| 模式 | 何时用 |
|---|---|
| 存为草稿 | **第一次务必用这个**，去平台后台确认排版后再手动发 |
| 立即发布 | 确认适配没问题后再开 |
| 定时发布 | 入队 N 分钟后由浏览器执行（需保持浏览器运行） |

支持按平台单独覆盖；不支持自动发布的平台会自动降级为草稿，并在结果里标注原因。

### 3.4 发起同步

1. 打开源文章页（如公众号文章）
2. 点扩展图标 → 确认已提取到标题/正文/封面
3. 勾选要同步的平台（第一次只勾 1 个，比如知乎）
4. 点 **同步** —— 不再在弹窗里跑，而是自动跳转到独立 WEB 控制台 `#/sync`，
   当前文章与已选平台通过 `consoleHandoff` 一并交接过去

### 3.5 在控制台里完成并观察

控制台五个页面：

- **总览**：已登录/未登录平台数、近 7 天同步量、失败数
- **同步**：待同步文章、发布模式、平台选择、实时进度条与逐平台结果
- **账号**：每个平台登录态，「去登录」直接开对应后台
- **历史**：每次同步的记录与结果
- **失败**：失败明细，可「返回编辑」改完重发

操作顺序：

1. 进 **账号** 页确认目标平台是「已登录」（未登录就点「去登录」）
2. 回 **同步** 页，核对文章标题/字数，需要改就点「编辑」
3. 点 **开始同步**，看进度条逐平台推进
4. 结果含义：
   - `已发布` —— 平台侧已公开
   - `已存草稿` —— 去平台后台「草稿箱」能看到
   - `审核中` —— 知乎/掘金会轮询审核状态（首探 2s，之后每 5s，最多 30s）
   - `失败` —— 进 **失败** 页看原因
5. 失败处理：**失败页 → 返回编辑 → 改标题/正文 → 保存并重发**
   （正文快照只保留最近 10 份，更早的记录会提示正文缺失，只能重新提取）
6. 最后到平台后台（如 `zhihu.com` 创作中心）肉眼确认一次

**账号页的分层**：平台按发布能力分两层 —— 第一层「可直发」填完就能发，第二层「仅草稿」
只能填进编辑器或投稿页、需要人工提交。每张卡片上还有「图文类 / 资讯类」标签，只作标识、不影响分组。
完整的平台清单与各平台注册门槛见 [`平台分类.md`](./平台分类.md)。

### 3.6 小红书 / 头条号的特殊行为

这两个平台接口带 `_signature` / `x-s` 签名，只能在页面上下文生成，所以扩展会：

- 打开（或复用）你已经登录的创作者编辑器标签页
- 在页面里填入标题与正文
- 尝试触发平台发布按钮

结果三档：`已发布` / `已提交`（已点发布但未确认）/ `已填入`（内容已填好，需你手动点发布）。
**草稿模式下也会打开这个标签页**，这是预期行为。

v2.4.0 新增的网易号、企鹅号、36氪、虎嗅、界面新闻、简书、什么值得买、三个企业黄页，
以及仅草稿的 IT之家、InfoQ、快懂百科、百度知道，都走同一条页面驱动路线，行为一致。

## 4. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 加载扩展报「清单文件缺失或不可读取」 | 选错目录，必须选 `packages/extension/dist` |
| 报 `Could not load icon 'assets/icon-48.png' specified in 'action'` | zip 是 `Compress-Archive` 打的，条目名是反斜杠。用 `node scripts/pack-extension.mjs` 重新打包，或直接加载 `dist` 目录 |
| 从 zip 装后图标/页面 404 | 同上：zip 内部路径分隔符不对，解包后 `assets/` 变成了一个带反斜杠的文件名 |
| 弹窗空白 | 构建不完整，重跑 `pnpm build`；或扩展报错见 `chrome://extensions` 的「错误」 |
| 平台显示未登录但浏览器里已登录 | 目标后台在别的浏览器/无痕窗口；或 Cookie 已过期，点「去登录」重登 |
| 同步失败：找不到编辑器/接口 404 | 平台改版，适配器选择器需更新 |
| AI 报 404 | Base URL 必须带 `/v1`，或模型名不在中转站支持列表里 |
| 定时发布没执行 | 需要浏览器保持运行（误差 ±1 分钟） |
| 改了代码没生效 | 忘记 `pnpm build` + 扩展页「刷新」+ 刷新目标网页 |
| 控制台打不开 | 从弹窗「同步」按钮进入；或手动访问 `chrome-extension://<ID>/src/console/index.html` |

## 5. 更新与卸载

- **更新**：`git pull` → `pnpm install`（依赖有变时）→ `pnpm build` → `chrome://extensions` 点「刷新」
- **卸载**：`chrome://extensions` → 移除。本地数据（AI Key、CMS 账号、历史记录）随扩展一起清除
- **日志**：`chrome://extensions` → 该扩展 →「Service Worker」可看后台日志；控制台页面按 F12 看前端日志
