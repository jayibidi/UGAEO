### 新增消息

`AI_LIST_MODELS` 仍然保留（返回扁平数组），老调用方不受影响。设置页已切到 `AI_LIST_MODEL_LIBRARY`。

### 分类规则

1. 网关给了 `supported_endpoint_types` → 按声明分：含 `image-generation` 归 image，含 `chat` / `completion` 归 chat
2. 没给声明 → 名称兜底：`*-image*` / `dall-e` / `seedream` / `flux` / `stable-diffusion` / `kolors` 归 image；`embedding` / `whisper` / `tts` / `rerank` / `moderation` / 视频类归 other
3. **图生图编辑类不算生图模型**：`*-inpaint` / `*-edit` / `flux-kontext` / `upscale` / `remove-bg` 归 other。
   它们的入参需要原图，直接拿来做文生图必然 400

## 二、登录态检测：默认不再开标签页（破坏性行为变更）

### 接口变更

```ts
// core/src/types.ts
export interface AuthCheckOptions {
  /** 是否允许「开页实测」，默认允许 */
  probe?: boolean
}

export interface AuthResult {
  isAuthenticated: boolean
  needsProbe?: boolean   // 新增
  // ...
}
```

```ts
// core/src/adapters/types.ts
checkAuth(options?: AuthCheckOptions): Promise<AuthResult>
```

**影响面**：所有适配器的 `checkAuth()` 实现签名从无参变成可选参。已有的无参实现**不需要改**（TS 允许少参数），但如果你的适配器内部调用了 `this.probeAuth()`，需要按 `options.probe === false` 时提前返回 `{ isAuthenticated: false, needsProbe: true }`。参考 `page-publish.ts:1149` 的实现。

### 调度变更

```ts
checkAllPlatformsAuth(forceRefresh = false, options: AuthCheckOptions = {})
```

- 默认 `probe: false`。`background/index.ts` 里的启动预检、悬浮按钮、`CHECK_ALL_AUTH` 全部显式传 `{ probe: false }`
- 只有三处放行实测：
  1. 账号页单平台「重新检测」（`CHECK_AUTH`，payload 带 `probe: true`）
  2. 自检页点检测（`options.forceRefresh === true` 时）
  3. MCP server 显式检测
- `refreshPlatforms` 加在途去重（模块级 `refreshInFlight`），`boot()` 与 Accounts 页 focus 监听并发时只跑一遍

### 为什么要这么改

5 个平台（八方 / 黄页88 / 简书 / 企鹅号 / 快懂百科）的登录身份存在服务端 Session，只能开标签页看会不会被踢回登录页。这些平台原先被三条路径同时触发，表现是「一进控制台就闪一堆平台页」。

### 兼容性注意

- `needsProbe: true` 的平台**不是未登录**。UI 上必须区分三态：已登录 / 待检测 / 未登录
  - 不要用 `!isAuthenticated` 判断「未登录」，要用 `!isAuthenticated && !needsProbe`
  - 待检测平台要照常进发布列表，否则企鹅号 / 简书会从列表里凭空消失
- `checkAllPlatformsAuth` 的返回项新增 `needsProbe` 字段

## 三、两处登录误判修复

### 微信公众号（`platforms/weixin.ts`）

原逻辑只匹配 `data: {... t: "..."}` 就判登录。未登录首页里也有 `t: "https://res.wx.qq.com/..."` 资源地址，于是游客被判成已登录。

改为同时要求：

```ts
const token = tokenMatch?.[1] ?? ''
const userName = userNameMatch?.[1] ?? ''
if (!token || /^https?:/i.test(token) || !userName) return { isAuthenticated: false }
```

`user_name` 是 `gh_` 开头的原始 id，游客页没有。

### 百度知道（`page-publish.ts` 的 `NON_SESSION_COOKIE`）

游客 Cookie `BAIDUID_BFESS` 是 httpOnly，被 `findSessionCookie()` 的会话兜底当成了登录凭证。

黑名单新增：`BAIDUID` / `BAIDUID_BFESS` / `BIDUPSID` / `tt_webid`。
真登录仍靠 `BDUSS`（已在 `sessionCookieNames` 里声明）。

## 四、`saveAISettings` 并发覆盖

```ts
// 旧：读 → 合并 → 写
const current = await getAISettings()
const next = normalize({ ...current, ...patch })
await chrome.storage.local.set({ [AI_SETTINGS_KEY]: next })
```

改地址、填 Key、回填模型列表几乎同时发生（设置页多个 `onChange` 各自 `await`）时，后写的会把先写的盖掉。表现为**地址填了却打到默认中转站，报 401**。

已改为模块级串行队列，每次保存排队执行「重新读 → 合并 → 写」。

**写同类 settings 时请照抄这个模式**，不要在组件里做「读改写」。
